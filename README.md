# ai-agents-in-depth — 《深入理解 AI Agent》全书方法论 Skill

把李博杰《深入理解 AI Agent》（v2.0，2026-09-19 开源）整本书蒸馏成一个可被 AI Agent 按需调用的知识技能包：**1 个入口 + 27 张能力卡**。当你在构建、调试、评估或改进 LLM Agent 系统时，它会自动激活，把书中经过验证的工程结论直接送到 Agent 的上下文里——而不是让你翻 500 页书或靠模型自由发挥。

## 触发条件

**会触发**（命中任一意图即激活）：

- 构建 Agent：核心循环（ReAct）、上下文工程（KV Cache 布局 / 提示词 / Skills / 状态栏 / 压缩）
- 记忆与知识：用户长期记忆、RAG 知识库、智能体化 RAG、知识库写入治理
- 工具与安全：工具设计、MCP 治理、提示注入防御、执行工具安全栈
- Coding Agent 与故障恢复、异步 / 语音 / GUI 交互扩展
- 评估体系：任务定义、指标口径（Pass@k vs Pass^k）、LLM-as-a-Judge、失败归因
- 模型选型与成本、后训练路线（Mid-training / SFT / RL）、奖励设计、持续进化闭环、多 Agent 架构与失败防御

**不会触发**：

- 与 Agent 无关的通用编程、数学、数据科学问题
- 具体模型版本（如某模型的参数、定价、API 细节）——书中数据为 2026 年中快照
- 需要真实算力集群的模型训练实操与机器人真机部署
- Agent 社会 / Agent 经济等展望性讨论的具体落地

## 它能用来干什么

每个能力卡遵循统一结构：**R 原文（可直接引用的作者原话）→ I 阐释 → A1 书中案例 → A2 触发场景 → E 执行步骤（带完成标准）→ B 边界（什么时候不适用）**。

27 张卡按意图路由，典型用法：

| 你在做的事 | 它给出的东西（举例） |
|---|---|
| 设计系统提示词 / 上下文布局 | 前缀字节级稳定命中 KV Cache；动态信息一律追加末尾（加一行时间戳实测首 token 延迟 0.5s→3-5s、账单近乎翻倍） |
| 搭 RAG / 知识库 | 分块参数起点、BM25+稠密双路 + RRF + 重排序、recall@k 验收；统计/边界类问题必须离线提炼摘要卡（100 案例问比例必答错的反例） |
| 设计知识库写入 | PR 审核流：异源 Proposer/Reviewer 分权、CI 门禁、定期整理防"局部正确累积成全局混乱" |
| 写 Skill / 治理工具爆炸 | 渐进式披露的目录/正文分离；工具超百个时索引化（Cursor 实测 token -46.9%） |
| 定评估指标 | Pass@k 是能力上限、Pass^k 才是业务可靠性（p=0.6 时 Pass@5≈99% 但 Pass^5≈7.8%），口径由业务风险决定 |
| 决策"微调还是 RL" | 先诊断再选路线：pass@k 近零先补底座、格式不稳先 SFT、有奖励差异才 RL |
| 判断要不要拆多 Agent | 第一判据是信息增量：同文本辩论在等计算量下不优于单 Agent |

另有 `references/cheatsheet.md`（27 条一句话决策规则速查）、`glossary.md`（30 个术语按作者用法而非通用常识释义）、`overview.md`（全书概览）。

## 理念来源

全部内容出自《深入理解 AI Agent》（李博杰著，v2.0，2026 年 9 月开源发布）。作者为华为诺亚方舟实验室研究员，该书基于其一线 Agent 系统的构建实践。全书的三个核心论断构成本 skill 的骨架：

1. **Agent = LLM + 上下文 + 工具**——模型固定时，扩展观察空间与动作空间是最大的能力杠杆，"许多看似需要更聪明模型的问题，其实只是接口问题"
2. **Harness 是竞争力所在**——生产系统的绝大部分代码是约束、验证与纠正，而非让 Agent"能做事"（LangChain 只改 Harness，Terminal Bench 52.8%→66.5%）
3. **数据和环境比算法更重要**——Mid-training 定底座、SFT 定协议、环境与奖励定 RL 能学到什么

贯穿全书的五大设计模式（提议者-审核者、渐进式披露、只增不改、边界集+保留集、最小 diff+可回滚）被组织成卡间关联网络（Zettelkasten 式 `also_read` 链接）。

## 给出的建议是否可靠

**可靠性是这套产物的主要设计目标**，按证据链分四层说明：

**1. 每条建议有原文锚点。** 能力卡的 R 段逐字引用作者原话并标注章节，I/E 段的工程结论都能回溯到原文；不混入蒸馏者自己的观点。数字结论（如 RLVP 违规 3.71→0.66、上下文感知压缩 -75% token）均来自书中实验或其引用的公开数据。

**2. 提取过程经过三重验证。** 461 条候选提取后逐条核对：来源充分性（V1，能否在原文定位）、可执行性（V2，能否变成带完成标准的步骤）、任务增益（V3，对书中 32 项关键任务清单是否有覆盖价值）。32 项任务全部有归属、零遗漏（审计记录见仓库 `books/` 目录）。

**3. 触发精度做过压力测试。** 用独立盲测 sub-agent（未参与蒸馏、看不到预期答案）测了 15 个 prompt：7 个正面路由全部命中，2 个纯诱饵（不该触发）零误触，4 个跨能力混淆场景（27 张卡互相抢调用）全部判对，2 个边界场景判断合理；9 个代表任务的实际执行全部通过。


一句话：**它是"这本书的可检索、可引用、可执行版本"，不是"一个懂 Agent 的通用模型"**——超出原书能力域的问题它会明确说不，不硬套。

## 安装与使用

```sh
# 克隆到你的个人 skills 目录（Claude Code/Codex/Hermes Agent 等）
git clone https://github.com/Deepseain/ai-agents-in-depth.git
# 或复制 SKILL.md + references/ 两个部分即可
```

装好后无需手动操作：当你提出 Agent / RAG / 评估 / 记忆类问题时自动激活。也可以显式调用：

```
用 ai-agents-in-depth 帮我设计知识库写入的审核流程
@ai-agents-in-depth 我的 RAG 召回不准，怎么排查？
```
