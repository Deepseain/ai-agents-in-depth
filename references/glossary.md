# 《深入理解 AI Agent》术语词典

> 30 条核心术语,按"作者本人的用法"整理(区别于字典/常识义)。来源:candidates/glossary.md(阶段 1 术语提取器全量扫描核验)。

## A. 核心骨架

**Agent（Agent = LLM + 上下文 + 工具）** — 引言/1.1
"这个公式只描述 Agent 边界之内的实现，不包含 Agent 与之交互的 Environment。"三层说法:实现层(LLM+上下文+工具)/直觉层(大脑+眼睛+手脚)/学术层(Policy+观察空间+动作空间)。≠ 常识的"自主智能体"——作者靠三要素而非自主性界定 Agent;模型固定时扩展观察/动作空间是最主要的能力杠杆("许多看似需要更聪明模型的问题,其实只是接口问题")。

**ReAct 循环** — 1.1.5/2.2.3
三环节(思考→行动→观察)的迭代循环,"本质是通过不断追加轨迹来让模型持续推进任务"。≠ 思维链提示技巧。工程约束:累计缓存读取量随轮数近似二次方增长(全部上下文技术的动因);模型只发调用请求,框架负责执行。

**Harness（挽具）** — 1.1.3.1/1.2
"Agent 边界内、模型之外的运行与治理层":上下文管理+工具接口+约束+验证+纠正。≠ 框架的别称,≠ 模型之外的一切(沙盒内文件/外部数据库/用户属 Environment)。词源马具:"不是限制马的奔跑,而是把力量引导到正确方向"。生产系统绝大部分代码是约束验证纠正,而非上下文工具。

**Loop 工程** — 1.2.1/10.4.3.1
"由验证器而不是模型自己来判定'是否真的可以停'"。针对过早终止三形态(偷懒式假完成/过早放弃/假成功):"在验证之前,'完成'只是模型的一句宣称,不是证明"。瓶颈在验证器不在模型。范式五阶段层层包含:提示⊂上下文⊂Harness⊂Loop⊂Graph。

**工作流 vs 自主 Agent** — 1.2.4
工作流=预定义代码路径编排(确定性,提示注入最多影响单节点);自主 Agent=根据环境反馈实时决定路径。递进选择:先提示词→再工作流→最后才自主。反面教训:复杂工作流遇新例外就加节点,"架构越来越复杂,通用性却越来越差";Manus:"Less structure, more intelligence"。

## B. 五大设计模式(1.3 命名)

**提议者—审核者(Proposer-Reviewer,含 Sidecar)** — 1.3/4.6
产出与评判由不共享上下文的角色分别承担,评判方看产物本身而非产出方的推理过程;前提是自审不可靠(Huang et al.:GPT-4 无外部反馈的自审反降准确率)。异源互审(能力相近、不同家族);Sidecar 是只读变体,只看结构化调用数据以堵死注入话术。审核者不可修改测试/证据采集器/发布门槛。

**渐进式披露(Progressive Disclosure)** — 1.3/2.5.1
先给可检索目录再按需加载细节,"同时优化上下文预算与选择精度"。Skills 是最典型形态;分层检索/主动工具发现/Agent 发现都是变体。边界:触发依赖模型元认知。

**只增不改(Append-only)** — 1.3/3.1.2
状态以追加演进,换可缓存/可重放/可审计;KV Cache 前缀稳定性是其性能形态。重要边界:只约束原始事件记录;运行时上下文可以压缩重组——"轨迹是流水账,长期记忆是档案"。

**边界集+保留集 / 最小 diff+可回滚** — 1.3/9.2.2
任何修改同时在"应改变的样本"与"不应影响的样本"上验证;只测前者会把过拟合当进步。9 章明言只盯边界集会把模型训成"永远不敢收尾"。最小 diff 让归因成为可能。

## C. 上下文工程(第 2 章)

**上下文 = 静态前缀 + 轨迹** — 1.1.4-1.1.5/2.2.5
五组成部分:系统提示词+工具定义(静态前缀)、用户消息+模型回复+工具结果(轨迹)。≠ 对话历史——上下文是模型能感知的一切信息,含"有哪些手脚可用"。关键性质:"前面不能动、后面可以压缩"。API 无状态,每次调用由框架重建完整上下文。

**KV Cache / Prompt Cache / Chat Template** — 2.3
KV Cache=推理内部缓存已算键值对;Prompt Cache=跨请求复用相同前缀;Chat Template=结构化消息→线性 token 流的转换器。作者把缓存当"架构约束"而非事后优化:提示词排列首先由缓存经济性决定、子 Agent 须与父字节级对齐。三条铁律:前缀定下不改/动态信息追加末尾/不自行拼接消息(破坏思维链保留与来源区分)。

**Agent Skills** — 2.5
"能力模块化为可按需加载的知识包";目录(name+description)常驻、正文按需加载。description 是路由决策关键:"'何时该用我'比'我能做什么'重要得多"。≠ 插件≠工具——是"动态提示词包",配通用执行器即可保持工具极少(七个核心工具)。emit-once 追加,对缓存友好。

**Agent 状态栏** — 2.6
框架在上下文末尾注入的结构化状态摘要(工具计数/TODO/环境),作为 user 消息追加而非改 system。理论基础:"上下文学习更像检索而非推理","上下文窗口是一台只有一半的检索引擎"。三个非常识点:模型几乎无条件相信状态栏(须代码维护+防投毒)/它是有损投影(删原始记录有断崖风险)/两种更新实现缓存代价相反。

**上下文压缩(含上下文腐化)** — 2.7
三动机:长度成本/思考质量/上下文焦虑。"保留决策、约束、失败和来源的前提下提高历史信息密度"。隔离优于压缩:让大体积中间信息根本不进主上下文。上下文腐化(Context Rot):"溢出是装不下,腐化是装得下但找不到"——窗口没满也会发生。

## D. 记忆与知识(第 3 章)

**用户记忆(四种格式)** — 3.1
Simple Notes(原子事实)→Enhanced Notes(带上下文段落)→JSON Cards(三层嵌套)→Advanced JSON Cards(加 backstory/person/relationship/时间戳,解决"两个张医生"式消歧)。生命周期:读取→后台提取候选→来源与策略核验→更新。三套正交分类:层次(轨迹/长期记忆/业务状态)×格式×认知类型(情景/语义/程序)。生产默认混合模式。

**智能体化 RAG(含上下文感知检索)** — 3.3.4-3.3.5
"知识库检索不再是自动化的前置步骤,而是可供 Agent 随时调用的工具";价值在"'解决问题'而非'回答问题'"——简单问题传统 RAG 更快。易混辨析:上下文感知检索(索引期,给分块补前缀,做加法)≠上下文感知压缩(运行期,裁剪历史,做减法)。检索内容是间接注入的典型载体。

## E. 工具与代码(第 4-5 章)

**ACI 与工具生态(MCP/Skill Hub)** — 4.2/4.3
ACI(对标 HCI):让工具对 Agent 而非对人友好,"工具应对应 Agent 的目标而非底层 API 操作"。MCP=统一工具接入的开放标准;Skill Hub=注册表式分发。"是否用 MCP 协议"与"是否全量暴露工具定义"是两个独立决策。两条渠道都"把不受控制的文本注入上下文"——description 当不可信输入审计。

**Coding Agent + 文件系统** — 5.1
"以开放任务为目标的通用 Agent,核心是 Coding Agent 加文件系统"。成熟度最高"不是因为模型强,而是软件工程基础设施(测试/Linter/Git)天然构成 Harness"。适用边界(作者限定):主要适用于开放任务通用 Agent;垂直 Agent 中代码只是工具箱一员。

**代码元能力(Artifact 模式/生成式 UI/自举)** — 5.2
"能创造其他能力的能力":当场写出新工具/新约束/新表达形式。六维:思考工具/业务规则约束/多媒体生成/系统适配器/生成式 UI/自举。Artifact 模式:LLM 生成 SQL 代码交系统执行,"数据直达用户界面,绕过 LLM 中间人"。自举推荐"复制范例+适应性修改"而非从零生成。

## F. 交互扩展(第 6 章)

**事件驱动(异步 Agent)** — 6.2
输入统一建模为事件流;推送取代轮询。三策略:取消式(紧急,提前造安全点)/队列式(常规,安全点批量)/并行式(独立轻查询)。≠"代码用了 asyncio"——模型/API 是否支持该消息时序是前提;打断需占位符修复配对且防"已启动"被当"已完成"。

**快慢思考分离** — 6.3.5
前台快模型维持对话节奏,后台慢模型负责推理,"让交互能力与智能上限分别演进的模块化选择"。澄清"端到端"两义:语音通路端到端与认知架构端到端是两条独立轴。实证:Pine 快慢分离架构 τ³-Voice 第一。

## G. 评估与提升(第 7-9 章)

**Pass@k / Pass^k** — 7.2
Pass@k=1-(1-p)^k(能力上限,"技术奇观");Pass^k=p^k(业务可靠性)。p=0.6,k=5:Pass@5≈99% vs Pass^5≈7.8%。口径由业务风险决定:支付/退款盯 Pass^k,探索任务看 Pass@k。带副作用的操作不能"重试直到成功"。

**LLM-as-a-Judge 与 Rubric** — 7.5.1
Rubric 四准则:专家指导/全面覆盖(含陷阱)/按重要性加权(支持 Veto 否决)/自包含("引用了至少两个权威理论"而非"展示深刻理解")。已知偏差:长度/位置/同源(古德哈特定律——Agent 学会钻同家族 Judge 的盲点),缓解靠多源异构评判。能写成断言的继续用断言。

**失败归因 与 轨迹前缀回归** — 7.5.2-7.5.3
"归因对象是轨迹中的首个导致任务偏离的错误,后续错误往往只是连锁反应"。首错可能在 assistant message 上而非工具调用(T3A 案例:第 8 步思考);根因可能是 Harness 观察通道缺失而非模型能力。轨迹前缀回归的"答案应定义为可接受动作集合,而不是唯一的动作"。"获得一条信息和正确地将它用于当前决策是两种不同能力"。

**Mid-training / SFT / RL** — 8.1/8.7/8.16
"分别处理底座、协议与策略"。SFT 数学上=预训练(换了数据+loss masking),固化协议而非事实。诊断顺序:pass@k 近零→Mid-training;格式不稳→SFT;有非零成功率+可靠奖励→RL。"SFT 记忆、RL 泛化"是受控实验倾向非普遍规律。贯穿判断:"数据和环境比算法更重要"。

**RLVP(验证路径惩罚)** — 8.12.4
"奖励结果,惩罚路径":R=O+βΦ,Φ 由确定性规则逐动作计算。关键不是奖励更密,而是"恢复组内差异"(全败/全胜组零方差无梯度)。四纪律:只罚具体动作/结果奖励保留/每个惩罚配可达合规路径/规则难钻。≠ PRM(过程奖励可能锁死预设路径)。

**On-Policy Distillation(在轨蒸馏)** — 8.13
"学生决定走到哪里,教师负责在学生已走到的位置告诉它下一步的完整概率分布"——一条 rollout 产生约 L 组逐 token 监督。on-policy 修饰"谁采样状态前缀"(学生),与"谁提供监督"(教师)正交。前提:学生能进入教师可纠正的状态;采样/训练数值一致。

**持续进化(学习信号/四载体/睡眠学习)** — 第 9 章
三层验证(结果/过程/质量)出结构化学习信号;载体按"能力的表示性质"路由(知识/Prompt-Skill/程序/参数);双循环:在线记录证据、离线提案验证发布。核心区分:"保存经历不等于从经历中学习";安全三边界含"安全机制不可自我修改"。睡眠学习=离线整合的认知类比。即第 1 章发现循环(科学方法)的实验与反馈环节。

## H. 多 Agent(第 10 章)

**信息增量** — 10.2
多 Agent 价值的第一判据:"协作过程是否引入了单个 Agent 在生成时无法获得的新信息?"同文本辩论无新信息(等计算量不优,数据处理不等式);执行结果/渲染截图/外部验证有新信息(显著提升)。解释"学术无效 vs 工程有效"的矛盾。

**理解债与认知投降** — 10.5.6
六种失败模式中唯一"不是 Agent 的失败,而是人的失败":"Agent 交付越快,工程师对系统的理解落后越远"。"你可以外包你的思考,但不能外包你的理解"(Karpathy)。无工程对策,只有人的纪律。
