# 《深入理解 AI Agent》— 全书概览

## 基本信息

- **标题**: 深入理解 AI Agent（AI Agents in Depth，设计原理与工程实践）
- **作者**: 李博杰（Pine AI 首席科学家，图灵《AI Agent 实战营》讲者）
- **版本**: v2.0，2026 年 9 月 19 日开源发布
- **配套代码**: https://github.com/bojieli/ai-agent-book

## 一句话主旨

用 Agent = LLM + 上下文 + 工具 这一核心公式作骨架，讲清楚如何围绕模型构建 Harness（上下文工程、工具、评估），并沿"单体构建 → 能力提升（评估/后训练/持续进化/多 Agent）"把 Agent 工程从经验试错变成科学工程。

## 全书结构

- **第一部分（第 1–6 章）如何构建 Agent**：核心公式与 Harness 工程 → 上下文工程（KV Cache/提示词/Skills/状态栏/压缩）→ 用户记忆与 RAG 知识库 → 工具设计与治理 → Coding Agent 与代码元能力 → 交互扩展（异步/语音/GUI/机器人）
- **第二部分（第 7–10 章）如何提升 Agent**：评估方法论（一切改进的前提）→ 模型后训练（Mid-training/SFT/RL）→ 持续进化闭环 → 多 Agent 协作

一条暗线贯穿全书——发现循环（提案→证据→实验→反馈）：第 3 章建提案段、第 7 章建证据段、第 9 章建实验与反馈段。

## 五大设计模式（规范定义，第 1.3 节）

1. **提议者-审核者**：产出与评判由不共享上下文的角色分别承担，评判方看产物本身而非产出方的推理过程；成立前提是自审不可靠
2. **渐进式披露**：不把全部信息一次性放进上下文，先给可检索目录再按需加载；同时优化上下文预算与选择精度
3. **只增不改**：状态以追加演进；换来可缓存、可重放、可审计（KV Cache 前缀稳定性是其性能形态）
4. **边界集 + 保留集**：任何修改同时在其应改变的样本与不应影响的样本上验证；只测前者会把过拟合当进步
5. **最小 diff + 可回滚**：每次修改尽量小、带来源、可单独回滚；使归因成为可能

## 工程范式演进（1.2.1）

提示工程 ⊂ 上下文工程 ⊂ Harness 工程 ⊂ Loop 工程 ⊂ Graph 工程——层层包含；模型能力商品化后，竞争优势转移到模型之外的工程实践。

## 后记要点

- **两朵乌云**：①Agent 如何流式实时地与环境交互；②Agent 如何从与环境交互的成功失败中持续积累经验
- **模型与 Agent 共同演进飞轮**：模型会一层一层吃掉 Harness 但永远吃不完——训练以月计业务等不起、真实业务约束无法全部内化、每代模型打开新的能力前沿；"曾有人不换模型只改 harness，任务准确率 52.8%→66.5%"；harness 用于争取时间，长期护城河在技术之外
