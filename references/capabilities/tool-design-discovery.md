# 工具设计决策与爆炸治理

## R — 原文

> "默认取向:通用工具优于专用工具,除非存在明确的安全、权限或性能理由……但通用性也扩大了出错和攻击面。" —— 第 1 章 1.1.2 / 第 4 章 4.2.1

> "工具数量超过一百个时,即使最先进的大语言模型也容易在工具选择上出错……把'选哪个工具'变成'查哪条资料'。" —— 第 4 章 4.4

## I — 阐释

两个独立决策: ①能力做成什么形态——专用工具(JSON Schema 函数调用,确定可测但每条占数百 token)与 Skill(自然语言文档+通用执行器,目录只占几十 token)是一条谱系。默认往通用端靠,四种情况退回专用: 安全/权限/审计(支付、删数据)、参数复杂(嵌套对象、联合校验,结构化 schema 引导传参)、使用频率极高、屏蔽平台差异(grep/find)。四维决策: 安全权限/参数复杂度/变更频率(常变用 Skill 改文本)/模型能力(弱模型需 schema 引导)。②一次暴露多少条——工具到几百个时: 层次化组织按类分组 → 按需加载只暴露索引(Cursor 实测 -46.9% token)→ 检索式预筛选(按语义先筛再注入,49%→74%)→ 主动发现(Agent 声明能力缺口,系统两层语义路由匹配注入,schema 追加到轨迹末尾不破坏缓存)→ Skills 最轻(当资料查阅,免整套索引设施)。工具描述写"何时用+边界反例+参数具体示例+返回值+执行代价+1-5 个调用示例";参数保真是铁律: 禁止静默转换/注入。

## A1 — 书中案例

reported_case(第 4 章 4.2.3): Cursor 某版本把参数里的中文弯引号静默转直引号,读取工具却原样返回弯引号——模型看着文件里有、替换却"未找到匹配",反复失败且无法自诊;另一 IDE 的 bash 工具静默给 git commit 追加参数,旧版 Git 直接报错。治理侧(4.4.1): 5 个 MCP 服务器可引入数万 token 工具定义;Cursor 索引化 -46.9%;Anthropic 检索式预筛选使 Opus 4 工具使用准确率 49%→74%;MCP-Zero 在约 2800 工具上比全量注入省约 98% token。

## A2 — 触发场景

- 要给 Agent 加能力: 做成工具、Skill 还是直接 bash?工具描述怎么写?
- Agent 选错工具、传错参数、工具一多就"看不见"该用的
- 接入大量 MCP 服务器后上下文被工具定义吃掉、成本激增
- 语言信号: "工具设计", "ACI", "tool description", "专用工具 vs 通用工具", "工具太多", "tool discovery", "MCP 工具膨胀"
- 区分: 执行类工具的安全栈见 execution-tool-safety(本卡管形态/描述/暴露);Skill 的编写细节见 skill-authoring;频繁选错工具先查描述再疑模型

## E — 执行步骤

1. 形态决策(逐项能力过四维): 需精细授权/审计或不可逆风险→专用工具;参数嵌套复杂、多字段联合校验→专用工具(schema 引导);高频操作→专属入口;需屏蔽平台差异→专用封装;其余(可组合探索类)→通用执行器+Skill 或整合的通用工具(如 read_document 按 file_type 分流,避免 extract_pdf/extract_docx 碎片化)。完成标准: 每项能力记录四维判定。
2. 写工具描述: 何时用(决策导向,非功能罗列)/边界与反例("只匹配文件名,不能搜内容")/参数给具体示例(timestamp: 2024-03-15T14:30:00Z;phone: +8613888888888)/返回值结构/执行代价("需下载完整网页,5-10 秒")/1-5 个真实调用示例。完成标准: 新读者不看代码能正确调用。
3. 参数保真审查: 全链路无静默输入转换、无静默参数追加;确需规范化必须在描述中声明并在返回中告知。完成标准: 模型读到什么、工具就执行什么。
4. 披露策略(工具超过约 20-30 个时): 只在前缀放核心工具+工具搜索元工具;长尾工具名进索引,按需检索后把完整 schema 作为消息追加到轨迹末尾(首次加载后固定原位置);状态栏维护一份工具名列表。完成标准: 前缀 token 量与工具总数解耦。
5. 层次化与降级: 工具按服务器/类别分组,匹配先定位组再选工具;两层匹配候选均低于阈值时明确返回"未找到",让 Agent 改写需求、手工实现或造新工具——不强行塞最像的。
6. 验证: 选错率测试(注入工具前后对比);描述消融(移除描述文本看错误率);token 对照(全量 vs 索引化)。

输入契约: 能力清单及各自的风险等级、目标模型能力档位、工具总量预期。输出契约: 形态决策表+工具定义集+披露策略+验证记录。

## B — 边界

- 形态与披露是两个独立决策,勿混谈("走 MCP"≠"必须全量暴露 schema");Skill 与 MCP 也非互斥
- 通用执行器必须配沙盒(默认断网、限路径、限额)——通用性放大攻击面
- Skill 走自然语言传参,引号转义在跨平台命令行下比 JSON 更易错: 参数复杂时以 JSON 落文件再导入
- 黑名单只是最基础防护,可被变形命令绕过(语义解析见 execution-tool-safety)
- 主动发现的元认知前提: 模型得知道自己缺什么——弱模型上要靠状态栏与提示引导
- 工具描述是注入面: 第三方 description 当不可信输入审计(见 prompt-injection-defense)
