# 编写 Skill:渐进式披露机制与内容结构

## R — 原文

> "元数据中的 description 字段是路由决策的关键——'何时该用我'比'我能做什么'重要得多。" —— 第 2 章 2.5.1

> "一份实用的 Skill 不应只是背景知识……而应让一个刚加入团队的员工知道:遇到什么任务时使用它,应该按什么顺序行动,哪些情况需要停下来确认,什么结果才算完成。" —— 第 2 章 2.5.2

## I — 阐释

Skill 是把领域能力模块化的知识包,核心机制是渐进式披露: 目录(每个 Skill 的 name+description)常驻上下文、代价极低,完整正文按需加载,细则再通过文件引用逐层下探。这同时优化上下文预算与选择精度,且对 KV Cache 友好(正文在调用位置作为消息追加,不回写前缀)。内容结构四部分: 角色与读者说明(服务谁、输出标准)、核心原则(只留 3-5 条最重要的判断,每条配正例反例)、禁止清单(高频错误、越权动作、易误解表达,写清合法例外)、参考资料(术语表/模板/子文档)。规则写法是"作用域+动作+例外+验证方式",避免堆成越来越长的禁用词表。写 description 要像路由条件: 明确写何时使用、何时不使用并给典型反例,防宽泛误触发。

## A1 — 书中案例

worked_example(第 2 章 实验 2-7): 用 3-5 篇个人原创文章让运行时归纳初版写作 SKILL.md(约二十行),再用它起草新文章、作者逐句改稿,把 before/after 的稳定差异(删了哪些词、拆了哪些长句)写回 Skill——"原文与修改稿的差异比抽象地说'更自然一点'更有信息量"。另: PPTX Skill(2.5.1)三层结构——frontmatter 目录→核心流程(markitdown 提取/XML 解压)→html2pptx.md 等子文档,验证从论文 PDF 生成 10-15 页演示文稿(实验 2-6)。

## A2 — 触发场景

- 系统提示词膨胀到覆盖多业务场景,或要把领域能力做成可分发/可版本管理的模块
- 要写一个新的 SKILL.md,或现有 Skill 描述宽泛导致该触发不触发/不该触发乱触发
- 团队要把最佳实践沉淀给 Agent 复用("把这套流程做成 skill")
- 语言信号: "写一个 skill", "SKILL.md", "渐进式披露", "progressive disclosure", "提示词模块化", "能力包"
- 区分: 单场景内的一次性提示优化见 system-prompt-design;运行时状态注入见 agent-status-bar;工具太多时的发现机制见 tool-design-discovery(Skill 是其最轻量一层)

## E — 执行步骤

1. 定边界: 一句话回答"这个 Skill 在什么任务中被加载"——写不进一句话说明范围太宽,先拆分。完成标准: 能列出 2-3 条典型触发任务与 1-2 条"不该触发"的反例。
2. 写 frontmatter: name 唯一;description 用路由条件写法(何时用/何时不用/关键反例),控制在几十 token。完成标准: 只读 description 就能判断当前任务是否需要它。
3. 写正文四部分: ①角色与输出标准;②核心原则 3-5 条,每条带正例+反例;③禁止清单含合法例外;④参考资料引用子文档/模板/脚本。规则一律"作用域+动作+例外+验证方式"。完成标准: 新员工读后知道何时用、顺序、何时停下确认、什么算完成。
4. 组织分层: 主文件只放核心流程,细节拆子文档按需引用;可捆绑脚本与模板。
5. 迭代: 用真实任务跑一遍,把修改稿与产出的稳定差异写回规则;为每条规则保留正反例与适用范围。
6. 验证: 冷启动测试——目录中放着它,给一个应触发的任务和一个近邻反例任务,检查加载判断正确;加载后检查模型是否遵循正文指令。

输入契约: 领域的判断原则与流程素材(操作手册/范文/既有提示词)、典型任务清单。缺失处理: 无范文时先跑真实任务积累 before/after,不凭空编规则。输出契约: SKILL.md(frontmatter+四部分)+子文档+触发测试记录。

## B — 边界

- 规则总量小(几条)时不必上 Skill——直接进系统提示词更简单;Skill 的价值在规模化与可复用
- 原书警告: 模型不知道自己不知道什么时无法正确触发加载(元认知问题)——description 的反例写法是主要缓解手段,不彻底解决
- 第三方 Skill 是注入面: 安装来源不明的 Skill 前必须逐条审查内容(见 prompt-injection-defense)
- 与模型训练方法对齐: 选 Agent 交互模式应与模型厂商训练方式一致(如 Claude 的 Skills 生态),跨生态 Skill 支持度有差异
- 正文加载后"模型是否长期遵循"因模型而异——弱模型可能加载后仍不执行,需在目标模型上实测
