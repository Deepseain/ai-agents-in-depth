# Agent 状态栏设计与维护

## R — 原文

> "上下文窗口是一台只有一半的检索引擎……它缺了另一半:没有'提炼层'。任何'关于这些内容的结论',模型每次要用,都得从原始记录里现算一遍。" —— 第 2 章 2.6.1

> "Agent 状态栏在 API 层面实际上是作为一条 user 角色的消息插入到上下文末尾的,而不是修改开头的 system 消息。" —— 第 2 章 2.6.3

## I — 阐释

模型的注意力擅长"查找"不擅长"归纳统计"——"已经打了几次电话"这类结论分散在数千 token 的原始记录里,每次决策都要现算,代价高且常出错(数错次数→违反上限→循环拨打)。状态栏就是把隐式状态提炼成显式元信息,以极低成本呈现本需扫描全上下文才能获得的知识,并利用"末尾位置获得更高注意力"做强制性注意力引导。构成三类: 任务规划(TODO 列表防目标漂移)、事件侧信道(时间戳/间隔/位置)、环境观察摘要(系统时间、工作目录、工具计数、"该工具已被重复调用 N 次")。实现铁律: 作为末尾 user 消息追加(标签包裹如 <agent_status>),不改 system;用代码维护而不是让 LLM 批量统计(模型几乎无条件相信状态栏,写错它就当真)。

## A1 — 书中案例

worked_example(第 2 章 实验 2-8): 客服 Agent 已拨打 Xfinity 3 次后用户追问"能不能再打"。对照组 A(无状态栏)热力图显示注意力分散、思考 token 体现数数过程,Qwen3-0.6B 经常违反 3 次上限继续拨打;对照组 B(末尾注入 `phone_call invoked 3 times (Xfinity: 3/3 max)`)注意力集中于状态栏、直接使用已提炼信息。结果: 小模型+状态栏准确率接近前沿大模型,每次迭代的思考 token/延迟/花费降约一个数量级。另(实验 2-9): TODO 使平均迭代 21→15;详细错误信息(四层含修复建议)使错误场景成功率 60%→95%。

## A2 — 触发场景

- Agent 数不清自己做过什么(重复调用、超次、忘记还剩什么任务)
- 长任务目标漂移、忘记原始约束;Coding Agent 不知道当前目录/git 分支
- 要让模型"知道现在几点/什么环境"但不敢动系统提示词
- 语言信号: "状态栏", "status bar", "TODO 列表", "工具调用计数", "让 Agent 感知状态", "为什么它数错了次数"
- 区分: 单条工具结果太大要压缩见 context-compression;知识要跨会话保留见 user-memory-system;本卡管"运行时状态的显式化"

## E — 执行步骤

1. 列隐式状态清单: 找出任务中模型必须"现算"的量——调用计数、约束余量、TODO 进度、环境(时间/目录/分支/OS)。完成标准: 每项标注对应的上限或规则。
2. 选维护方式: 计数与状态用代码确定性维护(全局字典+格式化注入);确需 LLM 提炼时逐条抽取再由代码汇总,绝不批量统计。完成标准: 无"让模型自己数"的项。
3. 注入实现: 每次调用前在消息列表末尾追加一条 user 消息,`<agent_status>` 标签包裹;在工具结果内也可就地标注("本次是第 3 次呼叫该商家")。完成标准: system 消息从未被修改。
4. 定更新策略: 状态小、更新间新增消息多、会话长度受控→持久追加(缓存友好,如 Claude Code <system-reminder>);状态大、更新频繁、轨迹长→每轮替换末尾状态(仅使短后缀失效)。判据: 状态 S、后缀 R、次数 N、缓存折扣 α,倾向持久追加当 αSN/2 < (1-α)R(文字判据;精确公式受 OCR 限制需回查原书)。
5. 验证: 对照测试有无状态栏的约束遵守率与思考 token 量;注入一条错误状态验证"模型会当真"的风险意识。

输入契约: Agent 的约束规则集(各类上限)、需要感知的环境变量、会话长度预期。输出契约: 状态栏构成方案+注入位置+更新策略+对照记录。

## B — 边界

- 状态栏是有损投影: 只提前算了"预想会被问到"的维度——只要有一个问题涉及未计算的维度,只留状态栏删原始记录会导致准确率断崖下降;原始上下文谨慎删
- 投毒风险: 状态栏被模型高度信任,数据源含外部内容时须先过滤(见 prompt-injection-defense)
- 动态信息不能放进系统提示词当"状态栏"用——那是 KV Cache 反模式(见 kv-cache-context-layout)
- 对无需状态跟踪的单轮任务无收益,纯增 token
- OCR 说明: 2.6.4 缓存代价公式的精确形式在转换文本中损坏,本卡采用其文字判据,数值决策前应实测缓存命中率
