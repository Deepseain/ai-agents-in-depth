# 用户记忆系统设计

## R — 原文

> "它不保存每句对话,而是用额外的 LLM 调用提取、压缩并审查对未来有用的事实……提取结果应同时满足三条规则:选择性、抽象化、结构化。" —— 第 3 章 3.1

> "实践中的选择标准是:关键且少量的数据用 Advanced JSON Cards 以保证可检索性;大量且非关键的对话事实用 Simple Notes 以降低成本;多数生产系统采用混合模式。" —— 第 3 章 3.1.3

## I — 阐释

用户记忆 = 会话结束后仍对特定用户成立的知识。生命周期: 会话中读取相关记忆进上下文;会话后由 LLM 提取候选(丢弃"搜索返回 3 条"这类短期细节、把"这次要靠窗"抽象为长期偏好、用可检索字段结构化保存);写入前做来源与策略核验;更新时处理冲突。格式沿表达力递增四档: Simple Notes(原子事实,便宜但割裂关联)、Enhanced Notes(带上下文段落)、JSON Cards(类别→子类别→键值,支持局部更新)、Advanced JSON Cards(加 backstory/person/relationship/时间戳,解决"两个张医生"式消歧)——按需混合,不追求最高档。更进阶用 User as Code 把状态写成带类型对象、规则写成函数,让聚合/冲突检测/约束执行由确定性代码完成而非 LLM 心算。压缩三层: 重要性评分(访问频率/时间衰减/情感强度/独特性)→聚类摘要→抽象泛化。隐私: 日志脱敏用本地模型(送云端脱敏违背初衷)。

## A1 — 书中案例

reported_case(第 3 章 3.1.6): Mem0 v2 在写入时消歧("住在北京"被"搬到上海" UPDATE 覆盖),一次错误更新不可逆丢历史;v3 改为只增不改(两条事实带时间并存)+混合检索+时间排序,LoCoMo 71.4→92.5、LongMemEval 67.8→94.4。worked_example(实验 3-2): 统一接口切换四种格式跑三层次评估集——Simple Notes 低成本通过基础回忆但在消歧/关联层失分,Advanced JSON Cards 在消歧最优但维护贵。

## A2 — 触发场景

- 要让 Agent 跨会话记住用户偏好/事实/关系("下次不用再问")
- 设计记忆写入流程: 提什么、怎么存、冲突怎么办、隐私怎么保
- 记忆库膨胀后检索不准、新旧信息打架
- 语言信号: "用户记忆", "user memory", "长期记忆", "跨会话", "个性化", "记忆提取", "Mem0/记忆框架选型"
- 区分: 共享知识库(面向所有用户)的检索与治理见 rag-pipeline/knowledge-base-governance(技术同源,本章区分只在尺度与来源);行为经验("该怎么做")见 continual-evolution;会话内状态见 agent-status-bar

## E — 执行步骤

1. 定验收口径: 用三层次框架建评估集——基础回忆(单会话精确存取)/多会话检索(跨时间跨对象召回全部相关信息并推理,如两辆车场景)/主动服务(跨会话关联预警,如护照过期)。完成标准: 每层有带细节的测试用例与 LLM-as-a-judge 评分方案。
2. 选格式: 按信息类别路由——偏好/关键人物关系等关键少量信息用 Advanced JSON Cards(常驻概览);大量对话事实用 Simple Notes;含硬约束与需精确计算的用户状态用可执行代码(User as Code: 追加日志+定期重建类型化状态)。完成标准: 每类信息有归属格式与理由。
3. 实现写入: 会话结束触发提取(选择性/抽象化/结构化三规则);候选带来源与时间戳;冲突时不覆盖——两条并存加适用条件,或按证据裁决;隐私字段先本地脱敏再落盘。
4. 实现读取: 常驻概览(JSON Cards 有界前缀)+按需检索原始细节(上下文感知检索补分块前缀,见 rag-pipeline);检索返回原始记录而非先摘要(保持可审计)。
5. 压缩维护: 低于重要性阈值的聚类归并;从具体事件抽象为稳定偏好;定期回原始数据整理(防摘要代代相传)。
6. 验证: 在评估集上跑分层成功率(实验 3-1 评估集结构可参考);对矛盾信息用例检查系统是追问、并存还是猜。

输入契约: 目标个性化场景清单、隐私合规要求、可用本地模型。缺失处理: 无评估用例时先手写每层 10-20 条再开发。输出契约: 记忆生命周期设计(格式路由/写入流/读取流/压缩策略)+分层评估结果。

## B — 边界

- 上下文学习是临时的: 把对话塞长上下文/向量库不等于学会了——保存经历≠从经历中学习
- fact-LoRA 类"写入参数"路线的直接提问可复述、间接推理失灵(存进去≠会取用),当前不作默认
- 写入侧的 UPDATE/DELETE 有不可逆风险,错误代价格外高——倾向只增不改+时间排序
- 评估口径先行: 没有三层次标尺就无法比较格式优劣(实验 3-2 的方法即为此设计)
- 多模态记忆(人脸/声纹)属前沿,文本记忆机制不覆盖
