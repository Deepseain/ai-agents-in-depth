# Computer Use:GUI 自动化 Agent 设计

## R — 原文

> "把定位变成选择题——先把界面元素标注好编号,模型只需从中选一个……就像考试中选择题比填空题更容易答对一样。" —— 第 6 章 6.4.2

> "Computer Use 的难点不只是让模型在截图上答对,而是让它在每一步之后重新确认现实是否仍符合计划。" —— 第 6 章 6.4

## I — 阐释

Computer Use 是"截图→多模态决策→执行→再截图"的闭环,三个设计维度: ①动作空间——Anthropic 参考实现分三类工具(GUI 鼠标键盘含逐字输入与等待、持久 bash、字符串替换编辑),可换模型驱动同一循环;②视觉定位三路线——结构化元素索引(DOM/Accessibility Tree 枚举可交互元素标 ID,最精确稳定,首选)、视觉标注 SoM(分割模型切候选区域标号,无需 DOM,适用原生软件/游戏)、纯坐标预测(需按训练分辨率做双向等比缩放,小元素密集界面精度差);③观察接口——屏幕不是静止的: 关键帧截图(小模型判变化)、音量门控转写、用文字描述画面留痕(多模态历史压缩)。进阶是世界模型: 行动前预测桌面状态差异,预期一致继续、偏离才重规划(推测执行提效)。核心纪律: "看懂界面"≠"完成任务",每步动作后必须重新确认现实;移动端的真正壁垒是商业模式(绕过广告变现链)而非技术。

## A1 — 书中案例

worked_example(第 6 章 6.4.2): 分辨率匹配——Claude 训练用 XGA/WXGA/FWXGA 三档,真实屏幕 2560×1440(16:9) 应等比缩到 1366×768 送模型,输出 (683,384) 反向映射回 (1280,720);硬拉进 4:3 会压变形致坐标系统性偏移。reported_case(6.4.5): 手机厂商在消费级手机集成 AI 助手自动操作微信/淘宝/支付宝,很快遭平台封杀——Agent 绕过广告与推荐变现链,结构性利益冲突短期难调和。

## A2 — 触发场景

- 要自动化操作网页/桌面软件/手机 GUI(无 API 的系统)
- 定位不准(点错位置)、界面一变就失败、步骤太多 token 爆炸
- 评估某任务该走 API/RPA 还是 Computer Use
- 语言信号: "computer use", "GUI 自动化", "browser agent", "视觉定位 grounding", "Set-of-Mark", "元素树"
- 区分: 有 API/CLI 的系统优先走代码路线(成本延迟稳定性全面占优,见 code-meta-capability 的系统适配器与 RPA 固化);Computer Use 是无接口系统的兜底;成功的操作序列应固化为代码复用(见 continual-evolution 的工作流固化)

## E — 执行步骤

1. 判断是否需要 Computer Use: 目标系统有 API/命令行→不走 GUI;只有界面且任务多样→Computer Use;重复性强的固定流程→先探索一次再固化(本卡管探索期)。完成标准: 有明确的"无 API 证据"再选 GUI 路线。
2. 设计动作空间: 按参考实现三类工具裁剪(点击/输入/滚动/截图/等待 + 持久终端 + 精确编辑);每类动作标注可逆性,不可逆操作(提交/删除/支付)前加确认。完成标准: 每个动作有可逆性标签,不可逆清单有确认点。
3. 选定位路线: Web 与提供 Accessibility Tree 的桌面→结构化元素索引(枚举可交互元素、标 ID、截图叠加边界框+文本列表);Canvas/WebGL/游戏/无树原生应用→SoM 视觉标注;均不可行→坐标预测,并按宽高比匹配目标分辨率做双向缩放,拒绝非等比拉伸。完成标准: 定位路线选择有结构化信息可得性依据;坐标路线已做分辨率双向缩放验证。
4. 建观察接口: 显著变化才截图(小模型判变化,频繁时可每秒 1 帧)、有声音时门控转写、每帧生成一句话描述入上下文(原图可被清出后描述仍在)。
5. 循环纪律: 每次动作后重新截图验证结果与预期一致;页面未稳定则等待;预期外状态→停下重新规划,不硬点。多步表单按 10-20 轮循环预算规划。完成标准: 任何动作后都存在一次重新观察,无"连点不看"路径。
6. 验证: 标准任务(如表单填写)成功率、定位命中率(元素索引 vs 坐标)、每轮 token 与延迟;注入页面变化测恢复。

输入契约: 目标系统类型(Web/桌面/移动)、可用的结构化信息(DOM/Accessibility Tree 有无)、分辨率、可逆性边界。输出契约: 动作空间定义+定位路线选择+观察接口配置+成功率与成本记录。

## B — 边界

- 成本/延迟/稳定性全面不如 API 路线——能用代码就别用截图点击
- 坐标预测对训练分辨率高度敏感,不匹配即系统性偏移;非标准控件与动态元素使标注可能不完整——需保留回退路线
- "能在截图上答对"的基准分数不等于"能完成任务"(OSWorld-Human: 成功率达人类水平时步骤数与耗时仍明显更多)
- 消费级场景的生态壁垒(平台封杀)是结构性约束,技术解决不了
- 反爬/CAPTCHA/数据中心 IP 信誉是现实障碍(实践中常需住宅代理)
