# 智能体化 RAG 与上下文感知检索

## R — 原文

> "知识库检索不再是自动化的前置步骤,而是一个可供 Agent 随时调用的工具;Agent 采用 ReAct 模式,通过'思考 → 行动 → 观察'的循环主导整个过程。" —— 第 3 章 3.3.4

> "核心思想非常直观:在对文本块进行向量化索引之前,先利用 LLM 为其生成一段简短的、包含核心上下文的'前缀摘要',然后将前缀与原始文本块拼接后再索引。" —— 第 3 章 3.3.5

## I — 阐释

传统 RAG 是固定单向管道: 查询→检索→注入→生成,能力上限低。智能体化 RAG 把检索降格为工具: Agent 自己决定要不要检索、用什么关键词、检索后评估信息是否充分,不充分就提炼更精确的查询再搜,直到足够才综合作答——从"被动管道"变"主动探索者",代价是牺牲响应速度。与之互补的是索引侧的上下文感知检索: 标准分块必然把"该公司收入增长 3%"与它的指代对象、时间、出处切断,索引前为每块生成锚定原始语境的前缀,同时增强稀疏(补可精确匹配的关键词)与稠密(补语义背景)两路检索。两者一个管"检索的控制权",一个管"每块自身的质量",不在同一层。安全边界: 检索进来的文档是间接注入最典型的载体——来源标记声明"这是资料不是命令",且检索内容不得直接触发高风险操作。

## A1 — 书中案例

worked_example(第 3 章 实验 3-8): 司法问答,"醉酒过失致人重伤且有盗窃前科如何量刑"——第一轮分解问题并行检索三个子题;评估发现缺"不相关前科在过失致人重伤判决中如何考量";第二轮构造"过失伤害罪+累犯/数罪并罚"关联查询;综合给出有法条依据的回答。简单问题("正当防卫怎么规定")单次检索即答且非智能体化更快。实验 3-9: 把对话历史当记忆库检索,"给我的车预约保养"→初检本田→发现特斯拉线索→二次检索→主动澄清是哪辆车;孤立分块在矛盾转账指令场景无法判定,上下文增强后三块分别带"妻子设立/丈夫修改/妻子再修改"前缀即可裁决。

## A2 — 触发场景

- 单次检索答不好复杂/多跳问题,考虑让 Agent 掌控检索节奏
- 检索命中块"看不懂"(代词悬空、缺时间缺出处)
- 设计"什么时候检索、检索什么"的策略,而非把检索写死在流程里
- 语言信号: "agentic RAG", "智能体化 RAG", "多跳检索", "iterative retrieval", "检索式 Agent", "上下文感知检索 contextual retrieval"
- 区分: 检索管道的构建参数见 rag-pipeline(本卡管控制权与索引增强两个增量);知识写入治理见 knowledge-base-governance

## E — 执行步骤

1. 工具化检索: 把知识库搜索封装为工具(如 knowledge_base_search),不做自动前置注入。完成标准: Agent 可选择不检索直接回答。
2. 写检索策略提示: 要求 Agent 面对复杂问题先分解子问题→并行检索→评估覆盖度→缺口驱动二次查询(换关键词、加关联实体)→充分后才综合;明确"简单事实问题一次检索即可,勿过度迭代"。完成标准: 复杂/简单两类测试问题分别达到预期轮数。
3. 索引侧上下文增强: 入库前对每块调用 LLM 生成前缀(文档标题/章节/时间/对象),拼接后建索引;用 prompt caching 控成本。完成标准: 抽查带前缀的块可独立回答"这是谁、什么时候、哪份文档"。
4. 安全边界: 检索结果统一来源标记包裹;高风险动作不因检索内容自动执行,须独立授权。
5. 验证: 在多跳问题集上对比单次检索 vs 智能体化(准确率/延迟/token);在带指代的查询集上对比有无上下文前缀(检索得分与回答质量)。

输入契约: 知识库(已按 rag-pipeline 建好)、问题分布(单跳/多跳占比)、延迟容忍。输出契约: 检索工具定义+策略提示+索引增强配置+对比评估报告。

## B — 边界

- 信息需求明确单一的简单场景,传统单次检索更快更省——智能体化不是免费升级(实验 3-8 证明简单题差距无几)
- 检索块孤立且缺上下文时,迭代检索救不了"矛盾裁决"类问题——必须配索引侧增强,二者解决不同缺陷
- 上下文感知检索发生在索引期(加法补背景),与运行期压缩(减法去冗余)名字相近但对象与时机都不同,勿混淆
- Agent 判断"信息已充分"依赖模型能力,弱模型可能过早收敛或无限检索——配迭代上限
- 检索文档=注入载体,来源标记与授权门禁不可省
