# 评估驱动的模型选型与成本分析

## R — 原文

> "不要只看排行榜,要在你自己的任务上做评估……'仅稳定前缀'已经节省 28.3%,'仅压缩历史'又节省 17.5%,两者一起却只节省 30%,并不是二者相加。" —— 第 1 章 1.2.3 / 第 7 章 7.6.3

> "若在 n 个用例上测得成功率 p,标准误可粗略估计为 SE(p)≈√(p(1-p)/n)……'新模型 73% 对旧模型 70%'不足以支持切换。" —— 第 7 章 7.7

## I — 阐释

选型不是选最强模型,是在多维度间按评估数据权衡。维度: 吞吐与延迟要分 Prefill(定首字延迟 TTFT)与 Decode(定出字速度与思考时长);思考 token 量各模型差数倍且与效果不一定正相关,须在自己负载上实测;p95 尾延迟比均值更反映体验;成本按输入/输出/缓存 token 分价;能力指标按场景选口径(日常看 Pass@1,关键操作看 Pass^k,探索看 Pass@k/Best@k);预算-能力曲线——短预算领先不能外推长时能力(RE-Bench: 2h 预算 Agent 是人类 4 倍,32h 人类反超 2 倍),要报性能随预算变化的曲线。行为策略差异: 不同模型的默认行动阈值(先读多少再动手)不同且随模型保持——固定 Harness 换模可测。Agent 成本三层: 模型推理(上下文累积: 3 轮发 1000+2000+3000 而非 3×1000;思考 token)、工具调用(API 费+返回注入上下文的持续计费)、基础设施;优化(缓存/压缩/分层模型)收益不可加和,必须完整任务同开实测。统计纪律: 分差要过噪声带宽(SE 公式),配对分析(同任务逐题比,McNemar/bootstrap)优于两个独立成功率相减,多随机种子,能复现才切换。

## A1 — 书中案例

worked_example(第 7 章 7.6.3 表 7-4): 固定八轮客服退款任务,gpt-4o-mini 四组对照——无优化 $0.003776;仅稳定前缀 -28.3%;仅压缩历史 -17.5%;同开 -30.0%(压缩缩短了可命中缓存的前缀,故不相加)。工具返回随历史反复计费,八轮累计 9544 输入 token。另(实验 7-9): 固定中性 Harness 下 GPT-5.6-sol 首次修改前平均 6.89 次工具调用/4.67 文件,Claude Sonnet 5 为 4.56/3.56——行动阈值随模型变,两者测试均 100% 通过(策略无优劣,差异要测不要猜)。

## A2 — 触发场景

- 新模型发布/换 API 提供商,要决定"在我的任务上换不换、怎么换"
- Agent 成本失控或延迟不达标,要定位钱花在哪、优化什么
- 两个方案分数差 2-3 个百分点,纠结是不是噪声
- 语言信号: "模型选型", "选哪个模型", "成本分析", "TTFT", "p95 延迟", "思考 token", "统计显著性", "换模型值不值"
- 区分: 评估集怎么建见 eval-fundamentals;持续迭代改进闭环见 eval-driven-iteration;本卡管"选型与成本决策"

## E — 执行步骤

1. 建选型维度表: 输入/输出吞吐、TTFT、思考延迟(实测各模型思考 token 量)、p95 尾延迟、全口径成本(含缓存 token 价)、速率限制、鲁棒性(长任务是否模式崩溃)。每配置≥100 次请求,报 p50/p95/p99。完成标准: 维度表有实测数据非官方标称。
2. 能力实测: 在自建业务集上测各候选,按场景选口径(关键操作看 Pass^k);多随机种子(3-5 次)报均值与波动。
3. 行为策略观察(涉 Coding/长任务时): 固定 Harness 中性提示跑对照,记录首次修改前的工具调用数/读取文件数/时间——行为差异随模型存在,更换时可能改变系统行为。
4. 成本拆解: 追踪每次调用的输入/输出/思考 token、工具返回大小与反复计费量、端到端延迟;算每任务平均成本与 p50/p95/p99 分布。优化(稳定前缀/压缩历史/分层模型)各项做成独立开关,所有组合在完整任务上实测——禁止把单项节省比例相加。
5. 统计裁决: 分差>SE 噪声带宽(100 例 70% 时 ±9pp);同批任务做配对分析(逐题谁胜,McNemar 或配对 bootstrap);预期收益只有 2-3pp 而样本只有几十题时先扩样;正向结果独立复跑。
6. 决策输出: 差异化策略(如简单任务迁新模型省钱、复杂场景保旧模型保质量)而非全量切换;预算点覆盖接近真实任务时长的多个档位。
7. 成本护栏: 按任务类型/模型/用户维度监控,设单任务成本上限,Agent 陷入循环时自动终止。

输入契约: 自建评估集(见 eval-fundamentals)、候选模型清单与定价、真实负载的上下文长度分布。输出契约: 选型维度实测表+配对分析结论+成本拆解报告+分场景决策。

## B — 边界

- 公开排行榜不等于你的任务表现——新模型可能在你场景性能回退;有了评估集才做得了"为未来模型开发产品"的策略
- 便宜但成功率低的模型,重试后总成本可能反超——算成本-性能比而非单价
- 思考长度与效果不一定正相关,别按思考量付溢价
- 轻量模型路由要防误路由("9.9 vs 9.11 哪个大"式问题被判简单交给弱模型)
- 分层多模型组合本身有复杂度成本,整体效益要评估验证
