# Mid-training、SFT 与 RL 的选择决策

## R — 原文

> "Mid-training、SFT 和 RL 不是三种可互换的'微调力度',而是分别处理底座、协议与策略。" —— 第 8 章 8.16

> "数据和环境比算法更重要:Mid-training 语料决定底座补到了哪里,SFT 示范决定协议是否稳定,环境和奖励决定 RL 能探索并强化什么。" —— 第 8 章 8.16

## I — 阐释

四阶段: 预训练(预测下一个词,学语言/知识/推理)→Mid-training(在目标分布上继续语言建模,补领域知识与基础能力,全 token 计损,混通用数据防遗忘)→SFT(换了数据、只在回答上算损失的同一个任务,高样本效率地固化格式/风格/流程协议,不承载大规模事实)→RL(按奖励重新分配概率,探索示范外策略,代价常为 SFT 的几十上百倍)。选择靠两个前提诊断: 格式支持(输出无法解析则奖励算不了→先 SFT 固协议)与能力支持(留出集上固定温度采样测 pass@k: pass@k 近零说明成功策略不在模型分布内→先 Mid-training 补底座,RL 无法从全零奖励中凭空创造)。"SFT 记忆、RL 泛化"是受控实验倾向(GP 实验中 SFT 过拟合 J/Q/K=10、RL 学会重算),非普遍规律。LoRA 实践: 应用于所有主要权重矩阵(仅注意力层掉点)、学习率约全参 10 倍、SFT 用 rank 64-256/RL 用 8-32。动态事实走 RAG 不进参数;与 ICL/程序约束协同使用。陷阱清单 11 条(格式未稳上 RL、pass@k 近零上 RL、标称窗口当有效窗口、reward hacking、模拟失真、过度训练遗忘、数值失配、低估 RL 成本等)。核心原则: 大投入前先小规模验证关键假设,快速失败。

## A1 — 书中案例

worked_example(第 8 章 实验 8-11 GeneralPoints): 相同任务/模型/预算,Llama-3.2-Vision-11B 用"J/Q/K=10"训练——SFT 组测试时 J=11 仍按 10 算(规则 OOD -8.1%,视觉 OOD -9.9%);RL 组强化"重新计算直到正确"(规则 OOD +3.5%,视觉 OOD +17.6%,且改善了底层视觉编码器)。另(8.1.4): Llama-3.2-Vision 严格结构化输出下不经 SFT 直接 RL 完全失败(奖励无法计算);DeepSeek-R1-Zero 这类强基模可跳过 SFT——"必须先 SFT"只在格式/基本行为未建立时成立。

## A2 — 触发场景

- "模型做不好这个任务"——判断该补数据、微调还是上 RL,还是根本不用训练
- 决定知识放参数、RAG 还是提示词;要开始一个微调项目前做预算与路线规划
- RL 训练不收敛/崩溃,回查前置条件
- 语言信号: "要不要微调", "SFT vs RL", "LoRA", "mid-training", "继续预训练", "pass@k 判断", "什么时候需要 RL"
- 区分: 奖励函数本身的设计见 reward-design-rlvp;问题案例转训练数据、经验该写进知识/Prompt/程序还是参数见 continual-evolution;本卡管"训练阶段的路线决策"

## E — 执行步骤

1. 先排除不改权重的方案: Prompt/工具/代码约束/上下文管理能解决的行为问题不训练;事实需频繁更新、要引用、要权限控制或要删除→RAG。
2. 测能力支持: 在目标留出集以固定采样配置测 pass@1/pass@k/部分进展率/格式解析率,人工审计失败原因。判停: pass@k 近零且失败集中于概念/语言/基础操作→转步骤 3(补底座);偶尔能做对但输出不稳定→转步骤 4(固化协议);已有非零成功率与可靠奖励→转步骤 5。
3. Mid-training(仅当缺底座): 目标语料高密度构造(原始文档+代码仓库+教材式推导+蒸馏的思维链与 Agent 轨迹),按能力配比,双重回放(通用保留数据+长度提升后的旧任务),多维门禁(领域集升、通用集不降、loss 降且 pass@k 动才有意义);小规模先验证配比再扩预算。完成标准: 小规模实验的门禁指标全绿后再扩预算;任一保留集下降即调混合比或学习率。
4. SFT 立协议: 数千到数万条高质量示范(人工种子+教师生成+拒绝采样三路组合,规则校验+抽检过滤,"精修一万条干净的不如堆十万条脏的");只在回答 token 上算损失;固化 JSON schema/工具调用/术语/流程/风格——不拿它硬塞知识库。完成标准: 留出集格式解析率稳定达标(阈值按任务先小规模评估设定),关键动作可被验证器可靠评分。
5. RL(仅当有探索空间): 确认当前策略能产出可评分且有奖励差异的 rollout、奖励忠实反映部署目标;组内全零/全一没有梯度,先设计可达的部分奖励或课程。LoRA 配置: 全矩阵、学习率≈全参 10×、rank 按阶段。完成标准: 小批 rollout 中组内奖励差异非零且独立测试集随训练改善,否则回到步骤 2/4。
6. 协同与护栏: 稳定领域知识→Mid-training;动态事实→RAG;硬约束→程序;高维风格/隐式策略→参数。每阶段配独立保留集与早停;训练前后跑"能力×长度"矩阵查退化。
7. 验证: 小批 rollout 先测(格式稳定性、pass@k、奖励差异、采样/训练数值一致性)再放大——快速失败优于大规模失败。

输入契约: 基础模型及许可证、目标任务分布与留出集、可用算力/预算、教师模型可得性。输出契约: 阶段决策记录(含 pass@k 证据)+数据构造方案+各阶段门禁指标。

## B — 边界

- "SFT 记忆、RL 泛化"是本书受控实验的倾向,数据多样/正则得当时 SFT 也能泛化,奖励有偏时 RL 也过拟合——引用时保留边界声明
- RL 训练时间可达 SFT 的 10-200 倍;测试分布与训练高度一致时 SFT 可能已足够
- 训练-推理数值失配会把名义 on-policy 变离轨: 监控 sampler/trainer 的 log prob 一致性,与奖励曲线同等重要
- 模拟环境的偏差就是训练的天花板(策略学到应试);模拟器需真实交互定期校准
- 蒸馏继承教师边界: 教师在长尾的系统错误会被学生硬编码;依赖工具的教师,输出蒸馏会丢工具鲁棒性
- 模型策略边界可能拒绝敏感任务(作者做 CoT 蒸馏被两家闭源 Coding Agent 拒绝)——训练管线选型时把策略合规当约束条件
