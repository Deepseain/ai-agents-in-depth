# 执行工具的安全机制栈

## R — 原文

> "模型感知到的世界与工具操作的世界之间,不能存在系统性的偏差。" —— 第 4 章 4.2.3

> "所有政策事实一律从数据库读取,绝不采信模型自报的值……最后一道防线必须建立在模型无法伪造的数据之上。" —— 第 5 章 5.2.2

## I — 阐释

执行工具改变世界,错误代价不可逆,安全靠多层栈而非单一机制: 输入验证(路径遍历/命令注入/类型格式,快速失败不"智能修正")→权限控制(限定工作目录、命令黑名单仅作基础层、配额限速)→沙盒(注意 venv 不是沙盒;隔离强度递增: 进程级/容器/microVM,配资源限额与超时)→提议者-审核者(不可逆操作事前审批: 异源模型配对、底层规则一致但关注点分工、拒绝理由作为工具失败回灌轨迹;事后验证用模态切换——渲染成图再查、沙盒里真跑,而非同模态重读)→Sidecar(与主模型流式输出并行的轻量门控,只读结构化字段 {tool, command} 防话术操纵,配拒绝熔断)→自动验证闭环(写文件后立即 lint,错误作为工具返回的一部分)→幂等性(唯一标识去重或先查后改;非幂等操作如发邮件/转账用"预检-确认"两段式,失败不盲目重试)。政策执行的三重保障: 提示词规则供理解、工具参数作 checklist 引导核对、服务端数据库真值裁决——模型自报值仅用于比对告警。

## A1 — 书中案例

worked_example(第 5 章 5.2.2): τ-bench 航空取消政策编码——cancel_reservation 工具描述列五条政策,要求模型调用前查询订单逐条核对并填 expected_cabin_class 等自查参数(填参过程即强制 checklist,模型常在准备参数时就发现经济舱无保险不可取消,直接向用户提议替代方案);服务端一律读数据库真值+服务端时钟,模型自报值与真值不符时记 mismatch 告警(发现错误认知或注入)。实验 5-5: 小模型配三重保障后政策违规显著低于纯自然语言规则组。

## A2 — 触发场景

- 给 Agent 开写/删/执行/发送/支付类工具,设计防误伤方案
- 评审"这个 Agent 会不会一个错误调用造成事故"
- 定义哪些操作要人工确认、哪些自动放行
- 语言信号: "工具权限", "危险操作", "沙盒", "审批", "sidecar", "幂等", "不可逆操作", "命令注入"
- 区分: 分层护栏框架与上下文层防御见 prompt-injection-defense(本卡是执行层的具体机制栈);Coding Agent 的故障恢复体系见 coding-agent-harness;命令的语义解析属本卡输入验证的进阶形态

## E — 执行步骤

1. 风险分级: 全部执行工具按可逆性/权限等级/财务影响标低/中/高。完成标准: 高风险清单含删除、支付、对外发送、改生产配置等,且每项标注复核方式。
2. 部署基础层: 输入验证(路径遍历 `../`、命令拼接、参数类型,异常即拒绝)→权限(限定目录、禁用命令表、配额)→沙盒按输入可信度选级(可信本地→进程级+工作区限制;不可信/凭证敏感→容器或 microVM;默认断网、白名单代理放行、凭证不挂载、CPU/内存/磁盘/超时限额,超限返回结构化错误而非静默杀)。
3. 部署审查机制: 不可逆操作加事前审批(异源模型、能力相近、底层规则一致、关注点不同: 提议者任务导向/审批者风险导向,拒绝理由进轨迹)与事后验证(换模态: 生成文档→渲染检查;改配置→沙盒实跑)。单次工具调用加 Sidecar 门控: 只喂 {tool, params} 结构化字段,数百毫秒内判定,连续拒绝即熔断转人工。
4. 自动验证闭环: 结果可验证的工具在执行后立即自动验证(写代码→lint,返回结构化错误列表)。完成标准: Agent 下一轮能看到具体错误与修复建议。
5. 幂等与重试语义: 每个执行工具回答"取消/超时后副作用发生了没"——能幂等的用唯一 ID 去重或先查后改;不能幂等的(邮件/电话/转账)用预检-确认两段式,执行失败把详细错误交回主模型重规划,不重试。
6. 政策类操作三重保障: 系统提示词放自然语言政策(解释沟通用)→工具描述+可选 expected_* 参数引导调用前核对→服务端从数据库真值+服务端时钟裁决,自报值只做比对审计。
7. 验证: 红队用例(路径遍历/命令变形/越权参数/被注入后诱导高危调用)逐层测拦截;反向测合法操作放行率(防过度拒绝)。

输入契约: 工具清单与风险等级、可接受的延迟预算、可用的异源模型、合规要求。输出契约: 安全栈配置(分级表/审批规则/Sidecar 策略/沙盒选型)+红队与放行测试记录。

## B — 边界

- Sidecar 用轻量模型审查单次调用的分类问题(此命令危险吗),提议者-审核者审开放式思考需能力相近模型——两类审查对象不同,勿混用判据
- 黑名单可被 $(echo rm) 类变形绕过;生产级需命令语义解析(理解参数消费规则,识别 find -exec 嵌入 rm、curl 覆盖 crontab)
- 快速失败原则: 发现异常输入立即拒绝,绝不"智能修正"——静默修正制造模型无法诊断的系统性故障
- "展示与放行拆开并行"可让安全检查对用户隐形,但检查本身不可省
- 全自动审批链的目标是"即使被注入也执行不出去",不是"识别所有攻击"——别在识别率上过度投入
