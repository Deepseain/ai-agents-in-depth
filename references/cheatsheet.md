# 决策规则速查 — 深入理解 AI Agent（设计原理与工程实践）

| 能力 | 一句话规则 |
|---|---|
| Agent 核心循环的实现与上下文构成 | 无状态循环重发完整消息列表；四角色配对、工具定义走 tools 字段、必须有迭代上限 |
| KV Cache 友好的上下文布局 | 前缀字节级冻结，动态信息追加末尾，永不自拼消息；工具 schema 按需追加到轨迹即并入缓存 |
| 流程驱动的系统提示词与工具定义设计 | 流程 SOP 优先于规则堆砌；业务规则细化到可执行；工具描述写"何时用+边界反例+参数示例" |
| 提示注入的识别与分层防御 | 三层部署（上下文降成功率/执行层拦动作/数据层保底），单层必然失效；三要素齐备即高危 |
| 编写 Skill：渐进式披露机制与内容结构 | 目录常驻、正文按需加载；description 写成路由条件（何时用/不用+反例）；规则=作用域+动作+例外+验证方式 |
| Agent 状态栏设计与维护 | 用代码把隐式状态提炼成末尾 user 消息；状态栏被无条件信任，故必须代码维护、防投毒 |
| 上下文压缩策略设计 | 80% 阈值批量压 tool results、保留决策/约束/失败/来源；隔离优于压缩；与缓存收益不可加和 |
| 用户记忆系统设计 | 提取三规则+格式按需混合+冲突不覆盖（并存带时间戳）+三层次验收先行；本地脱敏 |
| RAG 管道构建：分块、混合检索、重排序与指标 | 递归分块→稠密+BM25 并行→RRF 融合→跨编码器精排；recall@k 验收；统计与边界类问题须离线提炼 |
| 知识库更新与治理：PR 审核流、定期整理与权限 | 知识库当代码库：变更走 PR（异源互审+CI）；增量更新+定期回原始数据整理；检索层权限下推 |
| 智能体化 RAG 与上下文感知检索 | 检索降格为工具由 Agent 掌控节奏（分解→检索→评估缺口→二次查询）；索引前为分块生成上下文前缀 |
| 工具设计决策与爆炸治理 | 四维决策形态（默认通用，安全/参数复杂/高频/平台差异退专用）；描述写何时用+边界；工具多则索引化+按需发现 |
| 执行工具的安全机制栈 | 多层栈：验证→权限→沙盒→异源事前审批/模态切换验证→Sidecar 只读结构化门控→自动验证闭环→幂等；服务端真值裁决 |
| Coding Agent 流程与故障恢复 | 完成标准=测试通过；四层故障各有检测/分级恢复/熔断/接管路径；错误路径禁再调 LLM |
| 代码作为元能力的六维应用 | 按作用对象分六维；数据类任务走 Artifact 模式绕过 LLM；产物有紧凑精确描述+精度要求才选代码路线 |
| 异步事件驱动的 Agent 设计 | 输入统一建模为结构化事件流；取消/队列/并行三策略按紧急度；打断用占位符修复配对、不伪造完成 |
| 语音 Agent 架构选择 | 三范式（级联/Omni/全双工）按延迟、打断、调试需求选；快慢分离让交互与智能分别演进；级联要流式化 |
| Computer Use：GUI 自动化 Agent 设计 | 截图-决策-执行-再验证循环；定位优先 DOM/元素索引（选择题优于填空题），每步后重新确认现实 |
| 评估体系基础：任务定义、指标口径与数据集设计 | 四组成部分（含用户认知边界建模）+环境五要素+口径按业务风险（Pass@k 上限 vs Pass^k 可靠性）+三来源数据集 |
| LLM-as-a-Judge/Rubric 与失败归因 | Rubric 四准则（veto 否决+自包含档位）；归因找首错（事实锚点比对/前缀二分）；产出两层回归任务（前缀答案=可接受动作集合） |
| 评估驱动的模型选型与成本分析 | 自建集实测+口径按场景；成本三层拆解、优化收益不可加和必须完整实测；分差过噪声带宽+配对+复现才切换 |
| 评估驱动的系统改进与内部评估基础设施 | 观察→假设→实验→验证；每轮只改一个变量，先查评测系统再动 Agent；子集通过只获复测资格 |
| Mid-training、SFT 与 RL 的选择决策 | 三阶段各管底座/协议/策略；pass@k 近零先补底座、格式不稳先 SFT、有奖励差异才 RL；先排除不改权重的方案 |
| 奖励设计与 RLVP：奖励结果、约束过程 | 来源/时机/信息量三维度选型不堆不可验证维度；R=r+βΦ 奖励结果惩罚路径；先测信号可达性 |
| 持续进化闭环：学习信号、四种载体与验证发布 | 三层验证出结构化学习信号→按能力表示性质路由四载体→双循环+边界集保留集验证→安全三边界（可信根不可自改） |
| 多 Agent 架构决策：信息增量与共享×拓扑 | 先过信息增量判据（无新信息就单 Agent）；共享 vs 隔离按流水线/并发需求；对等/管理者/去中心化各配移交包与预算 |
| 多 Agent 六种失败模式与防御 | 六模式各有对策——乐观锁/worktree、独立交叉验证、差异化防共因、预定义裁决、预算防失控、人不可外包理解 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
